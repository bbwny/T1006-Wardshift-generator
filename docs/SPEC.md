## 1. ภาพรวม

เว็บจัดตารางเวรพยาบาลวิชาชีพ (RN) สำหรับหัวหน้าหอผู้ป่วย 1 บัญชีอีเมล = ผู้จัดเวร 1 คน และมีสิทธิ์แก้ไขเต็ม (ไม่มีขั้นตอนอนุมัติวันลา)

ส่วนประกอบ:

| ส่วน | ที่อยู่ในชุดนี้ | หน้าที่ |
|---|---|---|
| Engine | `engine/src/engine.ts`, `engine/src/local.ts` | กฎเวร, ตรวจตาราง, ค้นหาตารางอัตโนมัติ (ใช้ได้ทั้งเบราว์เซอร์และเซิร์ฟเวอร์) |
| Entitlement | `engine/src/entitlement.ts` | กติกาสิทธิ์ใช้งาน (ฟังก์ชันบริสุทธิ์ เรียกในเซิร์ฟเวอร์) |
| Profile | `engine/src/profile.ts`, `engine/src/data/hospitals-th.ts` | ลงทะเบียนหน่วยงาน, ค้นหา รพ., event วิจัย |
| ต้นแบบ UI | `prototype/index.html` | หน้าตาและการทำงานจริง (ข้อมูลจำลองใน localStorage) |

## 3. ลงทะเบียนหน่วยงาน (ครั้งแรกหลัง Login)

บังคับก่อนใช้งาน ปิดหน้าต่างไม่ได้จนกว่าจะบันทึก แก้ไขภายหลังได้จากแถบสิทธิ์ด้านบน

| ช่อง | บังคับ | หมายเหตุ |
|---|---|---|
| โรงพยาบาล | ใช่ | ค้นหาจากรายชื่อ (`HOSPITALS` 186 แห่งตั้งต้น) |
| อื่นๆ + ชื่อ รพ. + จังหวัด | เมื่อไม่พบ | `custom=true` → ทีมงานตรวจแล้วเพิ่มเข้ารายชื่อ (แสดง "รอตรวจ") |
| ประเภทหอผู้ป่วย | ไม่ | `WARD_TYPES` |
| ยินยอมให้ใช้รูปแบบเวรเพื่อวิจัย | ไม่ (ค่าเริ่มต้นไม่ติ๊ก) | บันทึก `consentAt` และถอนได้ |

การค้นหา (`searchHospitals`):
- ตัดคำนำหน้า "โรงพยาบาล", "รพ.", "hospital" และช่องว่างก่อนเทียบ → "รพ.ท่าศาลา" = "ท่าศาลา"
- ค้นจาก ชื่อ, คำค้นเพิ่มเติม (ชื่อย่อ/อังกฤษ เช่น รามา, Siriraj), จังหวัด, ประเภท
- หลายคำต้องเจอทุกคำ เช่น "กรุงเทพ ภูเก็ต"
- คีย์บอร์ด ↑ ↓ Enter, Esc ล้างคำค้น · ตัวเลือก "อื่นๆ" อยู่ท้ายผลค้นหาเสมอ
- Guide word (ปุ่มคำแนะนำ): `GUIDE_WORDS` เช่น มหาราช, ประชานุเคราะห์, ศูนย์การแพทย์

**รายชื่อ รพ. เป็นฉบับตั้งต้น** ต้องตรวจทานกับรหัสสถานพยาบาล 5 หลักของกระทรวงสาธารณสุขก่อนใช้วิเคราะห์จริง กติกา: `code` ห้ามเปลี่ยน/ใช้ซ้ำ เพิ่มต่อท้ายเท่านั้น ระบบจริงควรย้ายเป็นตาราง `hospitals` ในฐานข้อมูล และมีหน้าแอดมินจับคู่ชื่อที่ผู้ใช้กรอก "อื่นๆ" เข้ากับรหัส

### ข้อมูลวิจัย (`RosterPatternEvent`)

ส่งเฉพาะบัญชีที่ `researchConsent=true` เมื่อ:
- `roster_generated` — สร้างตารางสำเร็จ
- `roster_exported` — ส่งออกสำเร็จ (หลังเซิร์ฟเวอร์อนุญาต)

เนื้อหา: รพ./จังหวัด/ประเภทหอผู้ป่วย, เดือน, หน้า 1/2, โย้หน้า/โย้หลัง, จำนวนคนต่อเวร, ตัวเลือกที่เปิด, จำนวนบุคลากรแยกระดับ, ผลตรวจ (ผ่านไหม, จำนวนข้อผิด, เวรคู่, ช่วง OFF ≥ 3 วัน)
**ห้ามมี:** ชื่อบุคลากร, หมายเหตุ, วันลารายคน, เวรรายคน
แนะนำส่งด้วย `navigator.sendBeacon` เพื่อไม่ให้หายตอนเปลี่ยนหน้า

ใช้วิเคราะห์ว่า รพ. ใดจัดรูปแบบเวรแบบไหน และใช้งานบ่อยแค่ไหน เพื่อพัฒนาฟีเจอร์เฉพาะ รพ.

## 4. Login

- Google Identity Services → ส่ง ID token ให้เซิร์ฟเวอร์ตรวจ
- อีเมล + OTP 6 หลัก (หมดอายุ 10 นาที, จำกัดการขอซ้ำ/การเดาผิด)
- OTP เบอร์โทร เฉพาะตอนใช้สิทธิ์ทดลองของผู้ใช้อีเมล; เก็บเบอร์เป็น hash (`phoneHash`) และตารางเบอร์ที่ใช้ทดลองแล้ว
- Session cookie แบบ HttpOnly + Secure + SameSite

ต้นแบบจำลองทั้งหมดใน `MockServer` (แสดงรหัส OTP บนหน้าจอ) — **ห้ามใช้ในระบบจริง**

## 5. API ที่เซิร์ฟเวอร์ต้องมี

ทุก endpoint ที่เขียนข้อมูลตารางต้องเรียก `canEdit()` ฝั่งเซิร์ฟเวอร์ก่อนเสมอ โค้ดในเบราว์เซอร์แก้ได้ จึงเชื่อไม่ได้

| Method | Path | ใช้ฟังก์ชัน | หมายเหตุ |
|---|---|---|---|
| POST | `/api/auth/otp` | — | ส่ง OTP ทางอีเมล |
| POST | `/api/auth/verify` | `newAccount` | คืน session |
| POST | `/api/auth/google` | `newAccount` | |
| GET | `/api/account` | `subscriptionActive` | สิทธิ์คงเหลือ, เดือนที่ใช้สิทธิ์, โปรไฟล์ |
| PUT | `/api/account/profile` | `validateProfile` | เก็บ consent log แยก |
| POST | `/api/phone/otp`, `/api/phone/verify` | — | ตรวจเบอร์ซ้ำ |
| POST | `/api/months/:month/activate` | `activateMonth` | ทำใน transaction |
| GET/PUT | `/api/months/:month/roster` | `canView` / `canEdit` | เก็บ state ของเดือน (rows, locks, notes, colors, prior, tail) |
| PUT | `/api/workspace` | `canEdit` (เดือนใดก็ได้ที่แก้ได้) | รายชื่อบุคลากร, การตั้งค่า, วันลา |
| POST | `/api/months/:month/export` | `validate` + `authorizeExport` | ตรวจตารางซ้ำด้วย engine แล้วนับครั้ง/ผูกวอร์ด → คืน token ให้สร้างไฟล์ (หรือสร้างไฟล์ฝั่งเซิร์ฟเวอร์) |
| POST | `/api/checkout` | — | สร้างรายการชำระเงินที่ Payment Gateway |
| POST | `/api/webhooks/payment` | `applyPurchase` | ตรวจลายเซ็น, idempotent ด้วย paymentId |
| POST | `/api/events` | `buildPatternEvent` | ทิ้งถ้าไม่มี consent |
| cron รายวัน | — | `purgeDue` | ลบข้อมูล, ส่งอีเมลเตือน, `wipeAll` |

รหัสข้อผิดพลาด (`EntitlementErrorCode`): `PHONE_REQUIRED`, `PHONE_USED`, `NO_CREDIT`, `NOT_ACTIVATED`, `EDIT_EXPIRED`, `TRIAL_EXPORT_LIMIT`, `WARD_MISMATCH`, `BAD_PACKAGE`, `BAD_MONTH` — UI ในต้นแบบจัดการทุกรหัสแล้ว (เปิดหน้าซื้อ/ยืนยันใช้สิทธิ์)

## 7. งานที่ยังค้าง / ข้อควรระวัง

1. **ตัวจัดเวรกับวอร์ดขนาดใหญ่ — แก้แล้ว (24 ต.ค. 2569)** engine เดิมจัดทีละวันและย้อนแก้ได้ทีละวัน จึงหาตารางไม่ทันเมื่อ RN มากกว่า ~9 คน ตอนนี้ใช้ `solveLocal()` (`engine/src/local.ts`): วางเวรทั้งเดือนก่อน แล้วย้าย/สลับ/โอนเวรระหว่างคนในวันเดียวกันเพื่อลดข้อผิด (simulated annealing) จนข้อผิดตามกฎบังคับเป็น 0 แล้วตรวจซ้ำด้วย `validate()` ทุกครั้ง
   - วอร์ด ≤ 8 คนกำลังหลัก (`SMALL_WARD`) ยังลอง DFS เดิมก่อน (ผลเหมือนไฟล์ต้นฉบับ) ไม่ผ่านจึงใช้ local search
   - `capacityCheck()` แจ้งก่อนค้นหาเมื่อเกณฑ์ขั้นต่ำรวมเกินเวรทั้งเดือน พร้อมวิธีแก้
